# 项目协作目录

这个目录用于让主线程、子线程和未来的新对话共享同一套项目上下文。

建议每次开启新线程前，先让它读取这里的文件，而不是重新解释整个项目。

## 文件导览

- `architecture.md`：当前架构、核心边界和长期拆分方向。
- `roadmap.md`：近期优先级和阶段目标。
- `/alpha-health`：部署后优先打开的只读健康面板，用来确认 Alpha/生产最小闭环状态和下一条 smoke 命令。
- `working-agreements.md`：多线程协作规则。
- `threads/`：不同协作线程的责任范围。
- `tasks/`：具体任务说明和任务模板。
- `decisions/`：已经确认的架构决策。

## 推荐工作方式

1. 主线程负责拆任务、定边界、审查最终结果。
2. 每个子线程只读取一个 `threads/*.md` 和一个 `tasks/*.md`。
3. 子线程只修改自己责任范围内的文件。
4. 完成后必须汇报：改了什么、验证了什么、还剩什么风险。
5. 主线程再决定是否集成、继续拆分或回滚方向。

## 新线程启动模板

把下面这段复制给新开的线程，然后替换具体文件名：

```text
请先读取 docs/working-agreements.md、docs/threads/frontend.md 和 docs/tasks/2026-05-next-steps.md。

你只负责 frontend 线程中允许的文件范围。
不要修改其他模块，除非你先说明原因并等待确认。

请完成任务文件里与你相关的部分，最后汇报：
1. 修改了哪些文件
2. 如何验证
3. 有哪些未解决风险
```
