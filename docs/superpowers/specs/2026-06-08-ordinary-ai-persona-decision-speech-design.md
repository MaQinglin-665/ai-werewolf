# 普通局 AI 人格、决策与发言质量设计

## 背景

用户指出普通狼人杀单人局真实 LLM 发言仍然像模板：首置位会把低信息局面说成全桌审计，后置位围绕空问题滚雪球，常出现“收益来源、发言链、收口、闭合、缺口、压力源”等内部黑话。样本 `tmp/ordinary-mimo-real-speech-seed91-day1-after-repeat-fix.md` 还暴露了三个更深的问题：

- AI 不像从自己的第一人称视角发言，而像在总结整张桌面。
- Day 1 低信息局会把“平安夜、女巫用药”强行变成压人材料。
- 后置位容易模仿前面已经发过的问题，导致发言同质化。

本设计把目标从“修几句 prompt”提升为普通局 AI 质量升级：单人局和联机房间应使用一致的普通狼人杀 AI 读局、行动和发言逻辑。

## 用户确认的目标

- 适用范围包括普通狼人杀单人局和联机房间。
- 单人局和联机房间的 AI 逻辑、决策和发言应一致。
- 第一优先级是发言可读性：用普通玩家能听懂的话表达意思。
- 必要狼人杀术语保留，例如平安夜、女巫、银水、对跳、查杀、金水和投票。
- fallback 也必须使用同样的普通玩家口语，但应尽量减少 fallback 触发。
- AI 需要更有情绪和人格，但方向是“稳定玩家类型”，不是夸张角色表演。
- AI 池现有配置能力可以优化，用户希望使用预设选项或滑块，而不是主要依赖自由文本。
- 第一版应深入影响发言、投票、夜间行动和 AI 池配置。
- 默认普通局 AI 应稳定绑定不同“真实路人局”玩家类型，而不是按模型名刻板绑定。
- 允许 AI 因玩家类型产生轻微误判、犹豫、跟风或策略偏差，但不能乱玩、越界知道信息或选择非法动作。
- 验收需要自动测试和真实 LLM transcript 两层证据。

## 非目标

- 不修改规则裁判、胜负结算或合法动作生成规则。
- 不把学级裁判主题的戏剧化人设迁移到普通局。
- 不以胜率提升作为第一验收目标。
- 不要求一次实现完整长期社交关系模型，例如记仇、保护固定朋友或复杂情绪记忆。
- 不修改 `.env`、密钥、数据库文件、生成音频缓存或公网部署配置。
- 不把一次真实 LLM 样本当作绝对质量证明。

## 设计方向

采用“共享普通局人格策略层”。

模型层继续只负责调用哪个真实 LLM、使用哪套 Base URL、模型名和密钥。玩家类型层负责狼人杀里的说话方式、思考偏好和行动策略。两层不要混在一起，避免继续出现“DeepSeek 就必须冷静审计、Mimo 就必须细节校验”这种模型名人格绑定。

第一版不重写全部 AI 架构，而是在现有结构上收敛边界：

- 复用并改造 `personaStrategyCards`，让它从模型人格摘要变成普通局玩家类型策略层。
- 复用 `riskTolerance`、`bluffing` 和 `preferences`，但把 AI 池展示改成用户能理解的预设/滑块。
- 将同一份玩家类型信号进入 `tableRead`、`actionProviders` 和 `speechProviders`。
- 确认单人局和联机房间构造 `AgentView` 时传递同一套 AI 朋友配置。

## 玩家类型

默认 AI 朋友应稳定绑定不同“真实路人局”玩家类型。类型名称和文案应尽量像玩家描述，而不是内部分析术语。

可选默认类型示例：

- 急性子冲票型：说话直接，容易先怀疑一个人，投票偏激进。
- 谨慎怕背锅型：经常保留判断，怕投错，容易要求别人先说清楚。
- 爱抓一句话型：会盯住某句没听懂的话追问，但不能无限复读。
- 容易跟风型：会受前面发言影响，但需要能解释为什么跟或为什么改口。
- 身份信息敏感型：更重视预言家、女巫、银水、查杀和对跳。
- 低调观察型：发言短，不急着打死别人，但必须留下一个真实疑惑。
- 情绪反应型：容易对离谱发言急、不满或犹豫，但不能把情绪当铁证。
- 临场改口型：能承认自己刚才想错了，用新公开信息说明为什么转向。

这些类型不是固定台词库。它们只影响权重、发言形状和行动取舍。

## AI 池配置

AI 池第一版使用预设选项和滑块，不要求用户写长人设文本。

建议配置组：

- 说话方式：直接程度、情绪强度、发言长短、追问倾向。
- 思考偏好：事实、身份、反应、投票、记忆的相对权重。
- 行动策略：冒险程度、跟票倾向、夜间进攻/保守倾向、悍跳/伪装倾向。

现有字段映射建议：

- `riskTolerance` 对应冒险程度和投票激进度。
- `bluffing` 对应伪装、悍跳、狼人带节奏和神职压迫边界。
- `preferences.logic` 映射为重事实。
- `preferences.identity` 映射为重身份信息。
- `preferences.vote` 映射为重投票动作。
- `preferences.emotion` 映射为重情绪和即时反应。
- `preferences.memory` 映射为重前后变化。
- `preferences.leadership` 映射为带队倾向。
- `preferences.deception` 映射为伪装倾向。
- `preferences.caution` 映射为保守/怕背锅。

旧配置兼容：

- 没有新玩家类型字段时，根据现有权重推断一个玩家类型。
- 导入旧 AI 池数据不能失效。
- 模型、TTS、密钥配置仍按现有规则处理，不导出密钥。

## 读局接入

`tableRead` 仍然只读取公开信息和当前座位合法可见的私密信息。玩家类型只改变“注意力”和“解释偏好”，不能提供额外事实。

示例：

- 急性子冲票型更容易把当前可疑发言转成投票压力。
- 谨慎怕背锅型更容易保留判断，但必须说出自己没听懂哪一点。
- 身份信息敏感型更重视公开身份声明、银水、查杀和对跳反应。
- 低调观察型可以不站死，但要留下下一轮能回看的具体疑惑。

Day 1 低信息局需要特别处理：

- 平安夜和女巫用药可以作为背景，不应自动变成压未发言人的理由。
- 首置位可以说“我现在信息少，先听谁怎么接女巫信息”，但不能说成全桌审计任务。
- 后置位要优先回应已经发生的具体发言，不要全员滚同一个空问题。

## 行动接入

`actionProviders` 的投票和夜间行动使用同一份玩家类型策略。

白天投票：

- 投票理由必须能对应自己白天发言中的疑惑，或者说明为什么改口。
- 允许轻微跟风，但需要表达成普通玩家理由，例如“我本来不想投他，但后面几个人说完，我觉得他那句确实没解释清楚”。
- 后置位不能只复读前面压力，必须有自己的理由、保留或转向。

夜间行动：

- 狼人刀人、预言家查验、女巫救毒等可受玩家类型影响。
- 急性子/进攻型狼人更容易处理公开威胁，谨慎型狼人更可能避开风险位。
- 身份敏感型预言家更可能查身份关系关键位。
- 谨慎型女巫更保守，情绪型女巫更可能对强狼面位置用毒。
- 所有夜间行动仍必须只选择合法候选目标，不得泄露夜间私密理由到白天公开发言。

## 发言接入

普通局发言应像玩家说出口的话。

真实 LLM prompt 应强调：

- 使用第一人称局内视角，只说自己听到的公开信息、自己身份允许知道的信息和自己此刻的想法。
- 不要像裁判、复盘工具或全桌上帝视角总结局势。
- 必要狼人杀术语可以用。
- 抽象黑话要换成普通话。
- 说清楚三件事中的一到两件即可：我怀疑谁、为什么怀疑、我想让谁回答什么。
- 情绪和人格可以出现，但仍像普通路人玩家，不做戏剧化表演。

黑话改写方向：

- “收益来源”改成“你为什么现在要怀疑他”。
- “发言链没闭合”改成“你前面说的是这件事，后面突然转到另一个人，我没听明白”。
- “收口”改成“你最后到底想投谁”。
- “缺口”改成“你有一句话没解释清楚”。
- “压力源”改成“刚才真正让大家开始怀疑他的点”。

这些词不需要一出现就 fallback。优先通过 prompt 和 repair 让模型改写。只有堆叠到读不懂、明显模板化或造成复读空转时才进入强处理。

## fallback 与 repair

目标是少触发 fallback，而不是靠 fallback 修 transcript。

处理顺序：

1. 真实 LLM 输出。
2. 基础合法性和事实边界校验。
3. 对黑话堆叠、上帝视角、重复空问题、口语不足等问题优先给 repair/retry。
4. 只有多次修复失败、越界泄露、身份声明误读、要求未发言/已发言玩家做不合理回应、明显读不懂时才 fallback。

fallback 要求：

- 也使用普通玩家口语。
- 根据玩家类型生成不同形状。
- 不出现“收益来源、发言链、收口、闭合、缺口、压力源”等抽象模板词。
- 不把低信息局强行写成审计报告。
- 不暴露隐藏身份、狼队信息或夜间私密判断。

## 单人局与联机房间一致性

一致性目标是：相同 AI 朋友配置在单人局和联机房间中生成同样形状的 `AgentView.persona`、玩家类型策略和 role card 信息。

需要检查：

- 单人局创建游戏时是否传入完整 AI 朋友配置。
- 联机房间创建或开局时是否保留同样的 AI 朋友配置。
- 房间 AI 自动行动是否调用同一套 `tableRead -> actionProvider -> speechProvider`。
- 房间内真人玩家存在时，AI 仍只能接已经公开的真人发言，不能像观战者总结全局。

如果发现房间链路丢字段，应补齐配置透传，而不是写房间专用 prompt。

## 测试策略

Focused tests：

- 默认 AI 朋友有稳定玩家类型。
- AI 池滑块/预设能更新 `riskTolerance`、`bluffing` 和 `preferences`。
- 旧 AI 朋友配置可被推断为一个玩家类型。
- 单人局和联机房间传入同一个 AI 朋友时，`AgentView` 中玩家类型信号一致。
- 普通局 speech input 包含第一人称、普通玩家口语、必要术语保留和黑话改写指导。
- 黑话堆叠和上帝视角优先触发 repair 指导，不直接变成常规 fallback。
- 普通局 fallback 不包含抽象模板词。
- action input 包含玩家类型策略，同时保持合法候选动作约束。
- `seatMemory` 记录的普通局意图不会以内部字段名或内部术语进入公开发言。

脚本和样本：

- 固定 `seed91` 普通 9p 真实 LLM Day 1 transcript。
- 统计 fallback 数、黑话命中、重复片段、重复问题、首置位/后置位误用。
- 有条件时跑本地 room smoke，确认联机房间 AI 也带同一套玩家类型策略。

建议验证命令：

- `npm run test -- src/ai/personaStrategyCards.test.ts src/ai/speechProviders.test.ts src/ai/actionProviders.test.ts src/ai/seatMemory.test.ts src/components/AiPoolClient.mobile.test.ts`
- `npm run test -- src/app/api/games/aiFriends.test.ts src/app/api/rooms/api.test.ts`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run smoke:room-action:vote` 或等价本地房间 smoke
- 一次真实 LLM transcript review，优先复用 `seed91`

真实 LLM 验收关注：

- 发言是否像普通玩家。
- 是否保留必要狼人杀术语。
- 是否避免抽象黑话堆叠。
- 每个 AI 是否有稳定但不过火的性格差异。
- 后置位是否不再机械复读前面的空问题。
- fallback 是否少，且 fallback 文案仍像普通玩家。

## 风险

- 当前工作树已有大量未提交改动，实现前必须重新检查相关文件，避免覆盖并行修改。
- `AiPoolClient.tsx` 已经较大，UI 改动需要尽量使用 helper 或小组件，避免继续堆叠。
- 过强校验会增加 fallback；黑话和口语问题应优先 repair。
- 过强人格会牺牲狼人杀可玩性；第一版应限制为真实路人局程度。
- 真实 LLM 输出有随机性，单个 transcript 只能作为主观样本，不是唯一证明。

## 成功标准

- 普通局 AI 默认呈现不同真实路人玩家类型。
- AI 池可以用预设/滑块调整说话方式、思考偏好和行动策略。
- 单人局和联机房间共享同一套普通局 AI 策略和发言质量标准。
- 真实 LLM 发言明显减少抽象黑话，改用普通玩家能听懂的话。
- fallback 口语化，且 fallback 触发数量不因口语质量规则明显上升。
- 行动和投票能体现玩家类型，同时保持合法动作、阵营目标和信息边界。
