# AI 池批量 LLM 预设设计

## 背景

当前 `/ai-pool` 已支持给单个 AI 配置 OpenAI-compatible LLM 和 TTS，也有手机端紧凑卡片、展开配置面板、快速新增 AI、对局 AI 模式切换和本局 AI 队列。

真实使用时的主要阻力不是缺少字段，而是配置路径太重：

- 每个 AI 都重复填写 Base URL、API Key、模型名。
- 手机端需要进入单个 AI 卡片并继续展开配置层级。
- 想把同一套 LLM 配置批量套用到多个已勾选 AI，但现在只能逐个保存。

本设计第一版只实现 LLM 批量配置。TTS 采用同一套预设和批量套用框架作为后续扩展目标，不在第一版实现。

## 目标

让用户可以先创建一个或多个 LLM 预设，再把预设批量套用到 AI 池里当前勾选的 AI。

第一版目标：

- 在 `/ai-pool` 顶部“对局 AI 模式”附近提供批量 LLM 配置入口。
- 手机端和电脑端使用同一套功能，只做响应式布局差异。
- 支持多个本地 LLM 预设：新建、编辑、删除、选择、记住上次使用。
- 支持连接测试，用户手动触发，明确提示会调用一次模型并可能产生少量费用。
- 支持两个批量套用动作：只填空白、覆盖所选。
- 套用后显示逐个 AI 的结果清单，便于核对。
- 保留 AI 原有人格、头像、打法模板和入场顺序，只替换 LLM 接口配置。

## 非目标

- 第一版不实现 TTS 批量配置、TTS 连接测试、voice 批量选择。
- 不把预设保存到服务端、数据库、`.env` 或仓库文件。
- 不做预设导入导出。
- 不改变开局时自动补齐的默认 AI。
- 不改变 LLM 发言、行动 schema、fallback 逻辑或规则引擎。
- 不强制测试成功才能保存或套用预设。

## 用户流程

1. 用户进入 `/ai-pool`。
2. 在“对局 AI 模式”附近看到“批量 LLM 配置”入口。
3. 打开面板后，选择已有预设，或新建一个预设。
4. 预设包含：
   - 预设名
   - Base URL
   - 模型名
   - API Key
   - 是否将系统提示合并进用户消息
5. Base URL 输入旁提供快捷填充按钮，例如 OpenAI、DeepSeek、OpenRouter、本地兼容服务。
6. 用户可以点“测试连接”。测试按钮旁显示提示：会调用一次模型，可能产生少量费用。
7. 测试结果分两层显示：
   - 接口连通性
   - 项目格式可用性，也就是一条最小狼人杀发言请求能返回可用文本
8. 用户选择“只填空白”或“覆盖所选”。
9. 系统只作用于 AI 池里当前勾选的 AI。
10. 系统显示结果清单：
    - 已填空白
    - 已覆盖
    - 已跳过
11. AI 卡片状态立即显示新的模型名和自定义 LLM 状态。

## 套用规则

批量套用目标是 `selectedAiFriendIds` 对应的当前勾选 AI。

“只填空白”：

- 对没有自定义 LLM 配置的勾选 AI 套用预设。
- 对已有自定义 LLM 配置的勾选 AI 跳过。

“覆盖所选”：

- 对所有勾选 AI 套用预设。
- 已有自定义 LLM 配置会被替换为当前预设的 LLM 配置。

内置默认 AI：

- 套用后生成带配置的自定义副本，沿用现有“保存到这个 AI”的行为。
- 自定义副本保留 nickname、basePersonaId、头像、风险倾向、诈身份倾向和偏好。
- 当前勾选列表中的默认 AI id 替换为自定义副本 id。

已有自定义 AI：

- 直接更新该 AI 的 LLM 配置。
- 不改变 id、昵称、头像、打法模板、TTS 配置和入场顺序。

自动补齐 AI：

- 不受批量预设影响。
- 只有用户明确勾选的 AI 会被修改，避免用户没看到的默认 AI 被静默改配置。

## 数据与存储

预设只保存在当前浏览器本地，和现有单个 AI 配置保持一致。

建议新增本地存储结构：

```ts
type AiFriendLlmPreset = {
  id: string;
  name: string;
  baseUrl: string;
  model: string;
  apiKey?: string;
  mergeSystemIntoUser?: boolean;
  createdAt: string;
  updatedAt: string;
};

type AiFriendLlmPresetState = {
  presets: AiFriendLlmPreset[];
  lastUsedPresetId?: string;
};
```

API Key 行为：

- 可以保存在本地预设里。
- 界面明确提示“仅保存在本机浏览器”。
- 测试连接时 API Key 只随当次请求发送到服务端。
- 服务端测试接口不落库、不写日志、不保存 API Key。
- 是否保存 API Key 由用户点“保存预设”决定。

## UI 结构

入口位置：

- 放在“对局 AI 模式”卡片附近。
- 让用户先确定真实 LLM / Mock，再处理批量模型配置。

面板内容：

- 当前目标摘要：当前勾选 AI 数量。
- 预设选择器：默认选中上次使用的预设，允许切换。
- 预设管理：新建、编辑、删除。
- 删除预设：弹确认。
- 预设表单：预设名、Base URL、模型名、API Key、系统提示合并开关。
- Base URL 快捷填充按钮。
- 测试连接按钮和结果。
- 套用按钮：只填空白、覆盖所选。
- 结果清单。

手机端：

- 使用同一个面板内容。
- 面板可用全屏或近全屏覆盖层展示，避免继续加深单个 AI 卡片里的展开层级。
- 第一版优先从顶部批量入口解决手机配置路径深的问题，单个 AI 卡片的深层配置保留为高级入口。

电脑端：

- 使用同一个面板内容。
- 可作为页面内卡片、侧栏或宽弹层呈现，具体实现跟随当前 `/ai-pool` 样式。

## 连接测试

新增测试能力应与现有自定义 LLM 调用路径保持一致，避免另写一套不真实的探针。

测试分两层：

1. 连通性测试：确认 Base URL、模型名、API Key 能返回文本。
2. 项目格式测试：发送一条最小狼人杀发言请求，确认返回结果能作为项目里的 AI 发言文本使用。

测试限制：

- 用户手动点击才运行。
- 保存预设和套用预设不强制要求测试通过。
- UI 显示费用提示和等待状态。
- 失败结果要尽量显示可操作原因，例如地址无效、鉴权失败、模型不存在、响应为空、返回格式不可用。

安全要求：

- 不记录 API Key。
- 不把 API Key 放进错误消息。
- 不把测试请求写入持久化日志。
- 测试接口只返回状态、摘要和可展示错误，不返回密钥或完整原始请求。

## TTS 后续扩展

第一版不做 TTS，但设计要给 TTS 留出同一套框架：

- 预设管理可扩展为 LLM/TTS 两类预设或统一服务预设。
- 批量套用可复用“只填空白 / 覆盖所选 / 结果清单”。
- 测试能力可复用“手动触发 / 费用提示 / 不强制通过 / 不保存服务端密钥”。
- UI 命名避免把批量入口永久限定为只能处理 LLM。

后续 TTS 预设可能包含：

- 预设名
- TTS Base URL
- TTS API Key
- TTS 模型
- voice
- format
- auth header

## 风险

- 真实 LLM 测试会产生费用，所以必须手动触发并明确提示。
- API Key 在浏览器本地保存仍有本机风险，UI 文案必须说清楚。
- 批量套用会生成自定义副本，可能让 AI 池列表变复杂；结果清单和卡片状态需要让变化可见。
- 连接测试如果复用真实调用路径，可能受上游网络、模型限流或供应商格式差异影响，失败原因要尽量清晰。
