# 学级裁判主题局固定角色 AI 设计

## 背景

`学级裁判主题局` 第一版已经具备本地入口、9 人环形桌、头像、发言立绘和本地素材包读取。下一步目标不是先接语音，而是让 9 个角色在狼人杀中的发言、推理、投票和夜晚行动真正带有人设差异。

这个功能只服务本地自用、朋友小范围试玩和私下录视频。它不进入 Public Alpha，不进入 `/rooms`，不影响默认狼人杀模式。

## 产品目标

主题局开局后，玩家应感觉到“这 9 个固定角色正在认真玩狼人杀”，而不是普通 AI 换了头像。

重点体验：

- 9 个固定角色自动入局，不再依赖首页 AI 池选择。
- 固定座位顺序，方便视觉、语音、素材和视频剪辑稳定。
- 角色卡同时影响发言、内心推理、投票倾向和夜晚行动偏好。
- 角色仍以阵营胜利为主要目标，只允许很轻度的性格偏差。
- 黑白熊可以更强搅局、嘲讽和挑拨，但不能破坏规则或使用上帝视角。
- 角色知道自己处于学级裁判风格的狼人杀桌，可以自然使用主题氛围词。

## 固定座位

主题局固定 9 人顺序：

1. 苗木诚
2. 雾切响子
3. 腐川冬子
4. 黑白熊
5. 江之岛盾子
6. 塞蕾丝缇雅
7. 十神白夜
8. 叶隐康比吕
9. 千早爱音

这次切片不做随机座位，也不做“AI 池套皮局”。进入 `学级裁判主题局` 后，系统自动构造这 9 个角色 AI。

## 本地角色卡

角色卡放在 ignored 本地文件：

```text
local-assets/class-trial-pack/personas.json
```

该文件不提交到 Git，不打包进公网版本。代码只提供读取、校验和注入能力。

建议结构：

```json
{
  "id": "class-trial-personas",
  "version": "local-2026-05-27",
  "characters": [
    {
      "id": "naegi",
      "displayName": "苗木诚",
      "seatId": 1,
      "basePersonaId": "logic",
      "styleTags": ["hopeful", "earnest", "mediator"],
      "speechStyleZh": "...",
      "reasoningBias": "...",
      "voteBias": "...",
      "nightActionBias": "...",
      "asVillager": "...",
      "asWerewolf": "...",
      "pressureResponse": "...",
      "relationshipHints": [],
      "catchphrasePolicy": "...",
      "forbidden": []
    }
  ]
}
```

字段含义：

- `id`：稳定角色 id，必须匹配主题素材包角色 id。
- `displayName`：局内显示名。
- `seatId`：固定座位。
- `basePersonaId`：复用现有 AI 池基础 persona 的策略底座。
- `styleTags`：短标签，给 UI、测试和 prompt 组装使用。
- `speechStyleZh`：中文对白框口吻。
- `reasoningBias`：内心推理关注点。
- `voteBias`：白天投票倾向。
- `nightActionBias`：狼人、预言家、女巫、猎人等夜晚/技能行动偏好。
- `asVillager` / `asWerewolf`：分阵营策略，避免角色卡泄露身份。
- `pressureResponse`：被怀疑、被查杀、被带节奏时的反应。
- `relationshipHints`：只作为语气和怀疑角度提示，不提供额外信息。
- `catchphrasePolicy`：允许很短的原作式口癖或短句，但不大段复刻原台词。
- `forbidden`：禁止泄露身份、编造不可见信息、规则外自爆或故意送局。

## 行为边界

角色卡影响策略，但不覆盖规则和胜利目标。

允许：

- 更像角色的说话方式。
- 更偏角色习惯的推理关注点。
- 轻微非最优选择，例如更谨慎、更强势、更爱挑拨或更依赖直觉。
- 短口癖、短日文感叹或原作式短句点缀。

不允许：

- 大段复刻原台词。
- 公网启用版权角色卡。
- 泄露自己或他人的隐藏身份。
- 使用系统没有给模型的信息。
- 黑白熊以主持身份干预规则。
- 为了表演故意乱投、乱刀、乱救、乱毒或持续送局。

## 黑白熊规则

黑白熊作为普通玩家入局，底层仍按自己的阵营认真争胜。

它可以：

- 嘴欠、嘲讽、拱火。
- 放大玩家矛盾。
- 用戏剧化语气制造压力。
- 更积极推动对跳和站边冲突。

它不能：

- 暗示自己知道全场身份。
- 以主持人身份宣布规则外结果。
- 破坏投票、夜晚行动或胜负流程。
- 无理由自毁阵营。

## 中文对白与日文语音稿

当前切片先接入中文角色卡和中文发言行为。后续 GPT-SoVITS 切片再加入日文语音稿。

长期链路：

1. AI 根据局势、身份和角色卡生成中文发言与行动理由。
2. 单独步骤把中文发言润色/翻译成日文语音稿。
3. 对话框显示中文。
4. GPT-SoVITS 播放日文。
5. 日文稿允许轻微意译，但不能改变推理信息、指控对象、投票意图或身份暗示。
6. 日文稿或语音失败时，只显示中文对白，不阻塞流程。

这次切片只为未来预留字段，例如：

```json
{
  "voiceProfileId": "kirigiri-ja-local",
  "voiceLocale": "ja-JP",
  "voiceRewritePolicy": "轻微意译，不改变信息"
}
```

## 数据流

主题局首页选择 `学级裁判主题局` 后：

1. `GameClient` 探测本地 `manifest.json` 和 `personas.json`。
2. 如果 `personas.json` 存在且 9 人完整，开局时自动构造固定 AI 阵容。
3. 如果 `personas.json` 缺失，仍允许视觉主题局启动，但显示“角色卡未启用”的本地提示，AI 使用默认行为。
4. 创建本地单机/观战局时传入固定 `aiFriends`。
5. `src/game/engine.ts` 已会保存 AI friend 配置到座位。
6. AI 发言和行动 provider 读取 seat 对应 role/persona hints，并注入 prompt。

## Prompt 注入策略

角色卡应进入两个层级：

- 发言层：改变语气、表达、质疑方式、被追问时的反应。
- 决策层：影响怀疑重点、投票倾向、夜晚行动偏好和轻度风险偏好。

注入时必须带约束：

- 只能依据自己可见信息。
- 角色风格不能覆盖阵营目标。
- 不能泄露隐藏身份。
- 不能编造未发生事件。
- 输出仍需满足现有 schema。

Mock provider 可以只做显示名和风格摘要。真实 LLM provider 才需要完整角色卡注入。

## 错误处理

- `personas.json` 不存在：主题局可继续，但提示角色卡未启用。
- 角色数量不足 9：主题局可继续，缺失角色回退默认 AI 朋友，并在首页显示缺失数量。
- JSON 格式错误：不阻塞默认模式；主题入口显示本地角色卡格式错误。
- 某角色缺字段：按默认安全策略补齐，禁止把不完整字段直接拼进 prompt。
- `/rooms` 和 Public Alpha 不读取该文件。

## 验收标准

1. 默认模式不受影响。
2. `/rooms` 不出现角色卡主题入口。
3. `local-assets/class-trial-pack/personas.json` 被 Git 忽略。
4. 首页主题入口能显示角色卡是否完整。
5. 学级裁判主题局开局自动使用固定 9 人角色。
6. 座位顺序与设计一致。
7. 牌桌显示的角色名与素材包角色一致。
8. 真实 LLM 发言能明显体现角色风格。
9. 投票和夜晚行动理由能体现角色偏好，但仍认真服务阵营胜利。
10. 黑白熊更会搅局，但不泄露身份、不破坏规则。
11. 缺少或损坏 `personas.json` 时有清晰降级，不影响默认游戏。

## 不做事项

这次切片不做：

- GPT-SoVITS 接入。
- 日文语音稿生成。
- 公开 Alpha 角色卡。
- 房间模式角色卡。
- 角色跨局记忆。
- 随机座位。
- AI 池套皮局。
- 大段原作台词复刻。

## 推荐实施顺序

1. 新增本地角色卡类型、校验和状态函数。
2. 新增 `/class-trial-pack/personas.json` 读取能力。
3. 创建 ignored 的本地 `personas.json` 示例和 9 个角色卡。
4. 主题局开局时构造固定 9 人 AI 阵容。
5. 将角色卡摘要写入 AI friend 配置，确保座位、显示名、头像和角色 id 稳定。
6. 在真实 LLM 发言 prompt 中注入角色卡。
7. 在真实 LLM 行动/投票 prompt 中注入角色卡。
8. 增加 focused tests 和浏览器 9 人观战局验证。
