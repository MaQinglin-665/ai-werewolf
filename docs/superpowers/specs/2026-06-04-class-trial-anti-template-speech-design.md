# 学级裁判反老套发言设计

## 背景

当前学级裁判主题局的 D1 发言已经经过多轮修复，但用户仍认为样本不合格。最新评审共识是：问题不只是 fallback，也不只是某些禁词泄漏；即使非 fallback、验证通过的真实 LLM 发言，也会出现老套感。

典型表现：

- 句式老套：先复述局势，再指出一个缺口，再留一个验证方向。
- 思路老套：所有角色都围绕同一条查杀、平安夜、验证空间打转。
- 角色老套：雾切永远像证据链审计，灯永远说声音，塞蕾丝永远说筹码。
- 对话老套：不像角色在互相试探、误会、躲闪、抗推、带节奏，而像轮流交分析作业。

用户确认的目标是 A + C：优先让角色发言有生命感，同时建立可反复验收的样本和评分体系。可以牺牲一部分稳定推理强度；只要不泄露身份、不违反公开信息边界、不明显乱玩，允许短句、情绪、误判、自保和临场反应。

## 核心判断

继续加提示词或禁词不是主方案。过去的修复已经证明，禁掉一种模板后，模型会换成另一种模板：

- 禁普通狼人杀模板，会变成 `结构/收益/验证空间`。
- 禁内部审计词，会变成 `声音没接上/证词没合上/筹码压这里`。
- 固定角色动作也会模板化，例如 `雾切切证词`、`腐川刺一句`、`灯听声音`。

因此优化目标应从“让角色更像某个标签”改为“让角色在当前局势下产生独立的局内状态和欲望”。发言要从临场状态长出来，而不是从角色关键词或狼人杀审计骨架长出来。

## 目标

1. 建立一个反老套验收层，能稳定指出样本为什么老套。
2. 让每个非 fallback 发言先有当回合临场状态，再生成台词。
3. 保留硬边界校验：身份、查验、时间线、公开信息、私密信息、阵营规则不能乱。
4. 降低“高玩狼人杀分析”在评分中的权重，避免把抽象结构分析误判为好发言。
5. 用固定 D1 查杀样本做第一闭环，先解决 9 人同场发言的相似性问题。

## 非目标

- 不优化 fallback。fallback 可以记录，但不是本轮主因。
- 不改 UI、音频、房间、部署或普通狼人杀局。
- 不追求每句都是最强狼人杀推理。
- 不建立固定台词库或固定角色动作表。
- 不把角色口癖作为主要质量来源。

## 设计原则

1. **状态优先于标签**
   角色感来自当回合欲望、压力、自保、误判、试探、控场、抗推、切割、装信、装不信，而不是固定的口头禅或动作槽。

2. **反重复优先于禁词**
   老套不是某个词的问题，而是发言骨架、思考焦点和对话关系重复。验收要比较同一局前后发言，而不是只扫单句关键词。

3. **硬边界和软质量分离**
   验证器只管不能错的事；质量评估器负责判断老套、角色弱、互动弱。不要让硬验证器把发言压回标准狼人杀模板。

4. **允许不完美的人味**
   可以短、可以偏情绪、可以误判、可以只抓一个小点。只要仍在玩狼人杀，并且不越界，就不强迫补成完整分析段。

5. **每轮只产生一个主动作**
   不要求同时完成身份判断、逻辑解释、投票边界、角色演法、后置问题。每个发言只需要一个清晰局内动作。

## 验收层设计

### 样本固定

第一闭环继续使用当前 D1 全员发言样本：

- 9 人存活。
- 1 号苗木诚真预言家。
- 1 号首验 3 号腐川冬子为查杀。
- 按 1-9 号顺序发言。
- 只评估非 fallback 发言；fallback 只记录数量和位置。

固定样本的价值是高压测试重复问题：所有人面对同一个强焦点时，系统是否仍能让角色产生不同局内状态。

### 四类失败

评分报告需要明确输出以下四类失败，而不是只给总分：

1. **句式重复**
   - 多人使用相似结构：复述事实 -> 抽象评价 -> 留验证。
   - 多人以 `听完了/收到/我先看/这条线先挂着` 等同质开场进入。

2. **思路重复**
   - 多人围绕同一抽象焦点打转，例如都说查杀太干净、验证空间不足、平安夜只是背景。
   - 后置位没有因为前面发言变化而改变自己的目标。

3. **角色标签重复**
   - 某角色只反复命中固定标签，而不是根据局势变化产生新反应。
   - 例：雾切每轮都是证据链，灯每轮都是声音，塞蕾丝每轮都是筹码。

4. **对话关系弱**
   - 发言之间没有压迫、回避、误会、试探、切割、装信、抢话语权。
   - 每个人像独立写分析，不像在同一张桌上互相影响。

### 报告输出

样本报告应保留原有分数，但新增：

- 每条发言的 `antiTemplateFindings`。
- 与前面 1-3 条发言的重复点。
- 本角色当回合是否有明确 `liveIntent`。
- 本发言是否改变了桌面互动关系。
- 全局重复骨架统计。

目标不是一次性自动完美评分，而是让下一次修改能看到具体方向：到底是句式重复、思路重复、角色标签重复，还是对话关系弱。

## 生成层设计

### 新增临场状态

在最终发言前，先为当前角色生成或计算一个不直接说出口的 `liveState`。它不是台词模板，而是当回合心理和局内动作。

建议字段：

```ts
type ClassTrialLiveState = {
  intent:
    | "self_preserve"
    | "test_reaction"
    | "seize_control"
    | "misdirect"
    | "soft_support"
    | "distance_teammate"
    | "stall"
    | "pressure_target"
    | "withhold"
    | "fake_being_convinced";
  emotionalPressure: "low" | "medium" | "high";
  target?: { seatId: number; name: string };
  privateMotive?: string;
  publicMove: string;
  risk: "safe" | "social_risk" | "vote_risk";
  mustAvoidRepeating: string[];
};
```

这些字段不需要全部暴露给 LLM，也不应成为固定输出格式。关键是让每个角色有一个“此刻想做什么”，例如：

- 苗木不是“希望型主角”，而是“真预言家必须把查杀钉住，同时怕大家把它当可商量观察”。
- 腐川不是“刺一句”，而是“被查杀后先自保，试图让苗木的确定感变成可疑压力”。
- 江之岛不是“结构分析”，而是“狼队想把查杀反转成苗木的收益问题，顺便观察谁会跟压”。
- 高松灯不是“听声音”，而是“不敢直接站边，但想抓住一个别人忽略的小反应来保护自己不被卷进去”。

### 生成顺序

推荐链路：

1. 从当前 `AgentView`、公开发言、身份、阵营、座位、角色卡生成 `liveState`。
2. 用 `liveState` 过滤和压缩现有 `tableRead` / `speechPlan` 材料。
3. 给 LLM 的主任务改成：按 `liveState.publicMove` 说一句局内发言。
4. LLM 不需要输出完整分析，也不需要覆盖全部狼人杀信息。
5. 生成后通过硬验证器检查是否越界。
6. 质量评估器再判断是否老套，但不直接把合法发言打回 fallback。

### Prompt 方向

Prompt 不再强调“更角色化”“不要模板化”这种泛要求，而是给当前回合的具体状态：

- 你现在不是总结局势，你是在达成这个局内动作。
- 你可以只抓一个点。
- 你不需要显得公正。
- 你可以误判，但不能伪造公开事实。
- 不要复用前面已经出现的主轴。
- 不要把角色标签当台词来源。

### 防止角色状态模板化

`liveState.intent` 不能按角色固定分配。它应受以下因素影响：

- 是否被查杀、被点名、被投票、被前置位保或压。
- 自己阵营和真实身份。
- 前面是否已有多人围绕同一主轴说话。
- 当前发言顺序是前置、中置还是末置。
- 角色关系只作为偏置，不作为决定项。
- 狼队是否需要切割、冲锋、搅混或装好人。

例如雾切可以在不同局面中：

- 冷处理苗木的查杀。
- 反问腐川为什么不直接给身份。
- 暂时装作接受查杀，观察谁急着跟票。
- 在末置位收束票型风险。

这样雾切不再等于固定“证据链”动作。

## 数据流

```text
AgentView
  -> tableRead / public memory / role card
  -> classTrialLiveState
  -> speech input compression
  -> LLM speech render
  -> hard boundary validation
  -> anti-template evaluation report
  -> sample markdown/json
```

`classTrialLiveState` 是学级裁判专用层。普通狼人杀局不使用它。

## 验证与测试

### 自动测试

新增或调整测试时优先覆盖：

- `liveState` 不按角色固定映射。
- 同一角色在不同公开压力下会产生不同 intent。
- 被查杀位优先有自保/反打/抗推状态。
- 狼队后置位可以产生误导、切割、装信、抢节奏，而不是只重复查杀分析。
- 低信息或短发言不因“不够完整”被硬验证器拒绝。
- 质量评估能标记四类老套，但不直接触发 fallback。

### 真实样本验收

第一验收样本仍然是：

```powershell
node tmp/class-trial-d1-all-speeches-score.mjs
```

通过标准：

- 非 fallback 发言中，不能连续 3 人使用同一主轴。
- 9 人里至少 6 人有可读的不同 `liveIntent`。
- 角色标签重复不能成为主要角色感来源。
- 报告必须指出每条低分样本的具体老套类型。
- 允许推理不是最完整，但必须像角色正在玩这局。

## 实施分期

### 第一期：验收层

先扩展 `tmp/class-trial-d1-all-speeches-score.mjs` 或抽出可测试评分 helper，加入四类老套识别和报告字段。此阶段不改生成逻辑。

完成后，当前坏样本应能被明确诊断为：

- 雾切：角色状态和动作不足。
- 十神：分析骨架强于角色欲望。
- 高松灯：短句有犹豫，但没有形成局内动作。
- 江之岛：分数高但可能仍有结构分析模板风险。

### 第二期：临场状态层

新增学级裁判专用 `classTrialLiveState` 模块，把角色当回合 intent 与公开局势连接起来。先用规则/启发式生成，避免把状态生成也交给同一个 LLM 后不可控。

### 第三期：接入 speech input

把 `liveState` 接入 `buildConstrainedSpeechInput` 的学级裁判分支。压缩或弱化会诱导模板化的材料，只保留当前回合最相关的一条公开动作。

### 第四期：样本回归

跑固定 D1 样本，比较修改前后：

- 总分不是唯一指标。
- 重点看四类老套数量是否下降。
- 重点读非 fallback 原文。

## 风险

- 如果 `liveState` 设计得太枚举化，会变成新的动作模板。
- 如果质量评估直接变成硬验证，可能重新推高 fallback。
- 如果只重写评分器不改生成，样本会更准确地暴露问题，但不会自然变好。
- 如果过度牺牲狼人杀逻辑，角色会像在演戏但不像在玩游戏；硬边界和 publicMove 必须保留。

## 最小完成定义

本设计的第一轮实现完成时，应满足：

- 有可读的反老套评分报告。
- 有学级裁判专用临场状态层。
- 固定 D1 样本的非 fallback 发言能显示不同局内 intent。
- 低分原因从“角色纹理弱”升级为更可行动的四类失败诊断。
- 不修改普通狼人杀局、UI、音频、房间和部署路径。
