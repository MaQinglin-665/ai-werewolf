# 路线图

## 当前阶段目标

让项目从“能跑的复杂 MVP”进入“可持续迭代、可真实试玩的游戏产品”。

优先级不是继续堆功能，而是先收口当前本地大改动，把产品叙事统一，并让技术债服务朋友试玩闭环。

## 当前收束主线

1. 收口当前本地大改动：先冻结 AI 发言、行动、桌面读法、AI 池和房间体验相关改动，跑完本地验证，再决定是否部署。
2. 统一产品叙事：README、当前发布状态、试玩说明和宣传素材都应一致表达“Public Alpha 小范围试玩”，不要同时说成纯本地单机版和公网多人版。
3. 技术债服务试玩闭环：只拆会影响进房、开局、行动、投票、刷新恢复、手机可读性和 AI 局感的技术债，暂缓和试玩无关的大重构。

## P0：稳定性和可维护性

- 拆分 `src/components/GameClient.tsx`。
- 为规则引擎补关键阶段测试。
- 明确 AI 只能选择合法动作，不能绕过规则。
- 保证 `npm run test`、`npm run lint`、`npm run build` 可作为基本验收。
- 修复或确认 README/源码中文显示乱码问题。

## P1：AI 对局质量

- 优化 AI 的桌面读法、怀疑值和阵营策略。
- 增强座位记忆，不让 AI 每轮像第一次发言。
- 增加模拟统计，观察狼人/好人胜率、fallback 比例、无效输出比例。
- 复盘页展示 AI 决策依据和失败原因。

## P2：体验升级

- 优化桌面 UI 信息密度。
- 改善主持音频与 AI 语音节奏。
- 增加更自然的发言节奏和可读字幕。
- 加强新手可理解性，但不要把页面做成说明书。

## P3：玩法扩展

- 多板子稳定支持。
- 更多角色。
- 更完整的警长流程。
- 多真人或账号体系。
- 对局存档、筛选和统计。

## 近期建议顺序

1. 收口验证：确认当前大改动的 diff 边界，跑 focused test、`npx tsc --noEmit`、`npm run lint`、`npm run build`，并保存 AI 质量评估结果。
2. 叙事统一：更新 README、`docs/current-release.md`、`docs/alpha-playtest.md` 和推广素材，让外部入口、能力边界、限制和反馈目标一致。
3. 试玩闭环：组织 5-10 人小范围手机试玩，只处理 P0/P1 问题，把 P2 体验记录到后续打磨队列。
4. 定向拆债：优先拆 `GameClient.tsx`、`RoomClient.tsx`、AI speech/action pipeline 中妨碍测试和试玩修复的部分；每次拆分都必须能解释用户可感知收益。
